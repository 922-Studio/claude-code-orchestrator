orchestrator · setup/docs-mcp + setup/research-mcp

Docs it can't hallucinate, research it can't run out of

Two MCP servers replace the one thing Claude can't do from memory: look up what an API actually does today. Library docs come from an index on this machine with no quota at all; open-web research runs through Exa, picked because its free tier is the one you won't hit.

docs · local · no limits exa · 20 000 req/month 9 libraries indexed reproducible via libraries.tsv

The decision: free-tier headroom, not features

Every candidate does roughly the same job well. What separated them was how long you can work before hitting a wall — and the winner is counter-intuitive. Context7, the obvious choice for documentation, has the tightest budget of the three.

ServiceFree tierWhat that means in practiceVerdict
Exa 20 000 req / month ~20× the others. Research bursts never hit it; $7 per 1 000 beyond. installed
Context7 1 000 calls / month
+ ~60 / hour		 Cut from ~6 000/month in Jan 2026. The hourly cap is the real problem — doc lookups fire constantly while coding, so one intense session can exhaust it. replaced by self-hosting

Why not just use the built-in WebSearch? It is US-only and returns titles plus short snippets, not page content. It stays as the zero-setup fallback — particularly for headless and cron sessions, which cannot complete Exa's interactive login.

How the two halves fit together

One lane never leaves the machine and answers "what does this API look like in the version we pin". The other reaches the open web for everything that isn't in a library's docs.

Ask the local lane

"How do I override a FastAPI dependency in a test?" — anything answerable from the docs of a library we pin. Exact, versioned, free.

Ask the hosted lane

"Has anyone hit this Linkerd webhook-cert failure?" — anything that lives in issues, blog posts, or release announcements rather than reference docs.

What the orchestrator owns — and what it deliberately doesn't

Everything needed to rebuild this on a fresh machine is committed. The scraped documentation itself is not: it lives in Docker volumes, is regenerable from libraries.tsv, and would otherwise add hundreds of megabytes of third-party prose to the repo.

Rebuilding it from scratch

A real sequence — each step depends on the one before it.

  1. Start the server and register it

    bash setup/docs-mcp/install.sh
# pulls the image, starts container 'docs-mcp' on :6280,
# registers MCP server 'docs' with Claude Code (user scope)

  2. Build the index

    15–30 minutes, network-bound. The server is stopped while this runs, because the crawler needs exclusive access to the store — the script restarts it afterwards either way.

    bash setup/docs-mcp/index-libraries.sh          # all libraries
bash setup/docs-mcp/index-libraries.sh fastapi  # just one

  3. Install Exa and authenticate

    claude plugin install exa@claude-plugins-official
# then restart Claude Code and run:  /mcp → exa → authenticate

  4. Restart Claude Code, then verify with a real question

    MCP servers load only at session start. And a hit list is not a correct hit list — check where the answer came from.

    setup/docs-mcp/mcpcall.sh list_libraries '{}'
setup/docs-mcp/mcpcall.sh search_docs \
  '{"library":"fastapi","query":"dependency overrides in tests","limit":2}'

Eight things that broke on the way in

All eight are in the SETUP.md Fix table. They are recorded because each one fails quietly — the setup looks installed and the answers look plausible.

SymptomActual causeFix
Container restart-loops, exit code 0 --protocol auto picks stdio when there's no TTY, reads EOF and exits cleanly. A success exit that looks like a crash. Run server --protocol http --host 0.0.0.0, as install.sh does
list_libraries lists a library, but searching it finds nothing Rows appear when a job starts, not when it finishes. This produced a premature "all 9 indexed" while half the queue was still running. Trust list_jobs and wait for completed
Search answers from a changelog instead of the topic page --max-pages is a hard cap spent in link order, so big low-value trees starve the pages you want. FastAPI's single huge release-notes page beat advanced/testing-dependencies/; ~20 translated doc trees ate the rest. Exclusions + a raised budget per library in libraries.tsv
Every search result appears twice A mirrored version tree — helm.sh/docs/ and helm.sh/docs/v3/ serve identical pages, so half the budget bought nothing and duplicates crowded out distinct hits. Exclude the /vN/ mirror; duplicate URLs in a result list are the tell
A library indexes "successfully" with one page Two separate causes, same green checkmark. A cross-host redirect leaves the crawl boundary — computed from the URL you gave — matching nothing (docs.pydantic.dev/latest/ now 301s to pydantic.dev/docs/validation/…). Or the site is client-rendered, so fetch mode sees no links at all (playwright.dev). --scope hostname + an include pattern, or --scrape-mode playwright. The script now flags any library under 5 pages and exits non-zero.
Exclusions configured, yet everything is still in the index The worst one. The MCP scrape_docs tool has no exclude parameter and drops unknown arguments without complaint. Raising the page budget at the same time buried the noise under enough real pages that searches looked fixed — so the wrong cause got credited. Index only through the CLI, which is why libraries.tsv holds literal CLI flags
mcpcall.sh: sh[@]: unbound variable macOS ships bash 3.2, which treats an empty array as unbound under set -u. Output vanished silently. The ${sh[@]+"${sh[@]}"} guard — don't remove it
Exa returns 401 Authentication required The plugin ships no API key by design; it authenticates interactively. /mcp → exa → OAuth. Expected before that step, not a broken install.

The pattern worth keeping Seven of the eight look like success. A clean exit code, a populated library list, a ranked hit list, an empty shell output, a config option accepted without complaint, a green checkmark on a one-page index — all read as "working". Two habits catch this class: verify with a real question whose answer you already know, and when a fix works, check that it worked for the reason you think. Here the exclusions got credited for a result that came from the page budget alone.

Living with it

Add a library

Append a row to libraries.tsv with a page budget and changelog/translation exclusions, then index-libraries.sh <name>.

After a dependency bump

The index is a snapshot. Re-run index-libraries.sh <name>, or refresh_version to re-scrape only changed pages.

On a new machine

The provision migration starts and registers everything at the next pull, then prints the one indexing command it deliberately won't run inside a git hook.

Why the community deep-research plugin was skipped

Its design is sound — Haiku scouts build a source corpus, Sonnet specialists cross-challenge findings, an Opus synthesizer writes the result. But the code is third-party (0 stars, last push May 2026) despite being listed in Anthropic's community index, and it builds on the built-in WebSearch, so it inherits the US-only limitation this setup exists to get past. The Workflow tool already provides deterministic multi-agent fan-out, which is the half that plugin reimplements.
